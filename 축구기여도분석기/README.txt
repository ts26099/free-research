축구 기여도 분석기
==================

선수 좌표 파일을 넣으면 선수별 기여도(SC · PR · PA · DPI · IPI)를 계산해
엑셀 표와 그림으로 내주는 프로그램입니다. 명령어를 칠 필요가 없습니다.

계산식은 방법론 문서 「지표 설계의 이론적 배경, 가중치, 환산 절차」의
수식 1~19 를 그대로 구현한 것입니다.


1. 실행
-------
윈도우   START.bat 더블클릭
리눅스/맥  터미널에서  bash start.sh

처음 한 번은 계산에 필요한 라이브러리를 자동으로 설치합니다 (2~5분, 인터넷 필요).
추적 프로그램(SoccerTracker)을 이미 쓰고 있다면 그 폴더의 venv 를 찾아 쓰므로
대개 설치 없이 바로 열립니다.

  ※ 이 프로그램은 영상을 직접 분석하지 않습니다. 추적 프로그램이 만든
    좌표 파일을 받아서 기여도를 계산합니다.
    영상 -> 좌표 : SoccerTracker (tracker.py)
    좌표 -> 기여도 : 이 프로그램


2. 쓰는 순서
------------
(1) 좌표 파일을 넣습니다
    · 창에 파일을 끌어다 놓거나 [파일 추가]
    · 추적 프로그램의 results/<영상이름>/tracks.csv 를 그대로 넣으면 됩니다
    · 이미 미터 좌표로 만든 csv/xlsx 도 됩니다

(2) 경기장 크기와 한 팀 인원을 맞춥니다
    · 프로 풀사이즈 105 x 68 · 7v7 유소년은 보통 60~68 x 40~47
    · 이 값에 따라 위험도 감쇠 거리 등이 자동으로 조정됩니다 (문서 수식 19)

(3) [경기장 보정] — tracks.csv 를 넣었다면 반드시 해야 합니다
    · 버튼을 누르면 영상을 고르고 화면에서 기준점을 클릭하는 창이 뜹니다
    · 경기장 지점(코너, 페널티박스 모서리 등)을 4개 이상 클릭하고,
      클릭할 때마다 그게 어디인지 목록에서 고릅니다
    · 네 모서리처럼 넓게 퍼진 점이 가장 정확합니다
    · 한 번 해두면 저장되므로 다음부터는 안 해도 됩니다
      (카메라를 옮겼거나 다른 경기 영상이면 다시 하세요)

    왜 필요한가 : tracks.csv 의 좌표는 화면 픽셀입니다. 카메라가 비스듬히
    찍으므로 화면 위쪽 100픽셀과 아래쪽 100픽셀은 실제 거리가 다릅니다.
    기여도 수식의 상수는 전부 미터 기준이라 이 변환 없이는 계산이
    성립하지 않습니다.

(4) [▶ 분석 시작]


3. 결과
-------
results_ipi/<파일이름>/
├── ipi_result.xlsx   선수별 / 프레임별 / 프레임메타 / PA프레임별 / 표본검사 시트
├── ipi_plot.png      DEF-OFF 평면 + 그 경기의 공간 통제 그림
└── log.txt           화면에 나온 내용 그대로

읽는 법
  IPI      최종 점수. 100 = 이 분석에 들어간 선수들의 평균, 15 = 1 표준편차
           ※ 다른 경기의 IPI 와 직접 비교할 수 없습니다 (기준이 다릅니다)
  유형     DEF-OFF 평면의 사분면. IPI 가 같아도 유형이 다르면 다른 선수입니다
           문서 §6.4 가 "IPI 하나만 보여주면 안 된다"고 못박은 부분입니다
  DEF_z    수비 종합 (SC 와 PR 을 합쳐 다시 표준화)
  OFF_z    공격 종합 (PA 를 표준화하고 측정 횟수로 신뢰도 보정)
  rho      신뢰도. PA 를 몇 번 쟀는지에 따라 0~1. 적게 쟀으면 평균 쪽으로 당깁니다
  IPI_adj  포지션(자기 골대까지 거리) 영향을 뺀 값

화면 맨 위에 나오는 것
  [검증]      계산이 정의대로 도는지 12항목
  [문서 검증] 방법론 문서의 숫자 예시 20개를 그대로 재현하는지
  [상수표]    각 상수가 A/B/C/D 어느 등급인지 (D = 아직 검증되지 않은 값)
  하나라도 FAIL 이면 아래 숫자는 보지 마세요.


4. 설정 설명
------------
정규화        z = 방법론 문서 값. rank 는 분포가 치우쳤을 때 쓰는 대안
골키퍼 제외   골키퍼는 골문 앞에 서 있는 것만으로 공간 점수를 쓸어담습니다
포지션 보정   IPI 를 '자기 골대까지 거리'로 회귀한 잔차를 함께 냅니다
PA 지수 학습  실제 패스로 지수를 추정합니다. 순열검정을 통과할 때만 채택합니다
심판 제외     class_name 이 referee 인 행을 뺍니다 (골키퍼는 남깁니다)

문서와 다르게 (기본은 둘 다 꺼짐 = 문서 그대로)
  압박 속도항에 거리 반영
      켜면 멀리서 달려오는 것만으로 압박 점수가 붙는 것을 막습니다.
      문서 수식 5 에는 없는 처리입니다.
  전진가치를 골대거리로
      켜면 측면 전환 패스가 '전진 0' 으로 깎이지 않습니다.
      문서 수식 7-3 은 공격 방향 전진 이득(Δx)을 씁니다.
  ※ 하나라도 켜면 결과를 "문서 수식대로 계산한 값"이라고 보고하면 안 됩니다.
    켜져 있으면 [상수표] 아래에 경고가 찍힙니다.


5. 안 될 때
-----------
창이 안 뜬다
  START.bat 을 오른쪽 클릭 -> 편집 으로 열어보지 말고, logs\crash.log 를 보세요.
  "tkinter 가 없습니다" 면 파이썬을 다시 설치하면서 'tcl/tk and IDLE' 를 체크하세요.

"필수 열이 없다: {'X','Y'}"
  좌표 열을 못 찾은 것입니다. tracks.csv 라면 fx,fy 를 자동으로 씁니다.
  직접 만든 파일이면 열 이름을 X, Y (또는 x, y) 로 바꾸세요.

"팀을 두 개로 못 나눴다"
  team 열이 필요합니다. tracker 의 0 / 1 / -1 은 자동으로 처리합니다.

"공 좌표를 찾지 못했다"
  공 행이 필요합니다. tracker 에서 공 전용 모델을 켜고 다시 뽑으세요
  (공 track_id 가 1000000 번대로 나옵니다).

usable 이 0~10% 로 너무 낮다
  화면 밖 선수가 많이 빠졌거나 공 검출이 끊긴 것입니다.
  원인이 '소유자 미판정'인지 '추적 인원 부족'인지 로그에 같이 찍힙니다.

IPI 가 대부분 비어 있다(-)
  한 팀이 관측 구간 내내 공을 갖고 있으면 한쪽은 수비 기록이, 다른 쪽은
  공격 기록이 없어 합칠 수가 없습니다. 공수가 오가는 더 긴 구간이 필요합니다.

선수 수보다 track_id 가 훨씬 많다
  추적이 끊긴 것입니다. 이 상태의 '선수별' 표는 선수를 가리키지 않습니다.
  추적 프로그램에서 프레임 간격을 3 -> 2 또는 1 로, 해상도를 640 -> 960 으로
  올려 다시 뽑으세요.


6. 파일 구성
------------

ipi_app.py             창

soccer_ipi_v8.py       계산 엔진 (터미널에서 단독 실행도 됩니다)

results_ipi/           결과
logs/                  오류 기록
